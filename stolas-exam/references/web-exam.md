# web 主檔的題型與出題

SKILL.md 判定為 web 模式時，出題前讀取。

## 為什麼考關係

web 主檔是速查表：每個條目只有位置、一句話白話版、在本主題中的角色，加上追問中收錄的比較表與比喻。完整拆解只留在聊天中，主檔刻意保持克制，所以 web 模式不考單一詞的機制深度 (那是 stolas-thread 的範圍)。web 的價值在於把一堆詞連成一張網，驗收就考使用者能不能沿著這張網的線走：每個詞掛在哪裡、為什麼掛在那裡、相連的詞差在哪、一串詞怎麼合起來解釋一件事。

## 題數與題型

每輪 3 到 5 題，至少涵蓋三種題型。

| 題型 | 考什麼 | 出題依據 | 範例 (AI 記憶機制) |
|---|---|---|---|
| 定位題 | 一個詞在主題中負責什麼，為什麼掛在某個詞底下 | 位置行、在本主題中的角色、子項關係 | 長期記憶為什麼要以 RAG 為前提，少了檢索這一步會卡在哪裡。 |
| 辨析題 | 兩個相連 (對比、並列) 的詞，關鍵差別在哪 | 對比與並列關係、收錄的比較表 | 上下文視窗和長期記憶都在「讓模型記得」，說出兩者在保存位置與保存時間上的差別。 |
| 串聯題 | 用兩到三個詞合起來解釋一個過程或因果 | 前提與因果關係、子項鏈 | 用上下文視窗、RAG、長期記憶三個詞，說明聊天助理怎麼在新對話中想起上週提過的事。 |
| 歸位題 | 給一個沒討論過的新情境，判斷涉及哪幾個詞、各扮演什麼角色 | 整張目錄樹 | 「某助理在長對話後期開始忘記開頭的指示」，這是哪個詞描述的限制，可以用哪個詞的做法緩解。 |

## 出題規則

- **每題至少牽涉兩個關鍵字**，或一個關鍵字和它在主題中的角色。只考單一詞定義的題目 (例如「什麼是 RAG」) 不出，那等於讓使用者背一句話白話版。
- **優先考有關聯線的詞**：目錄樹中標了關聯類型 (並列、對比、前提、因果) 的詞組是首選，子項鏈 (例如 K1 → K4 → K5) 適合出串聯題。
- **題目寫關鍵字的主名稱，不寫編號**。編號只是主檔的索引，使用者不需要記。
- **題目不洩漏關係**：要考的是「K4 為什麼是 K3 的對比」，題幹就不寫「與 K3 對比的 K4」。
- **歸位題的情境要新**：不能是對話中討論過的例子；情境中出現的新名詞附上足夠說明。
- **確認式寫入的詞**：使用者自己說明過理解的詞 (一句話白話版帶「依你的說法整理」)，同樣可以出題，優先放在串聯題與歸位題中，確認使用者能把它接上其他詞。
- **使用者只拆了一支**：範圍內的詞全在同一支時，串聯題沿這一支往下走，歸位題的情境選這一支能解釋的現象。
- **依據只用主檔與本對話的內容**：題目與評分要點不引入主檔與對話中沒出現的外部事實。主檔記載的內容與通用知識有出入時，以通用知識為準，在回饋中指出並更正主檔。

## 評分補充

評分規則依 `grading.md`，web 模式另外注意：

- **掌握**的核心是關係與理由都對。使用者說出了正確的關係但沒說理由 (例如只說「它是前提」)，算部分掌握。
- 使用者提出的關係和主檔不同，但理由成立 (例如主檔寫並列，使用者論證成因果且說得通)，算掌握，並在回饋中說明兩種理解的差別；確實比主檔更準確時，詢問是否要更新目錄樹。
- 回饋時，每題把涉及的關鍵字在目錄樹中的位置用一行文字列出，讓使用者看到這題在網上的哪一段。
