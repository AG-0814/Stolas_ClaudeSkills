# Stolas Exam：驗收

## 這個技能在做什麼

stolas-thread 與 stolas-web 只負責講解，講過不等於學會。本技能用文字作答的題目確認使用者能用自己的話重建概念，作答證據是「已掌握」的唯一來源。

| 來源 | 考什麼 | 題型與規則 |
|---|---|---|
| stolas-thread 教材 | 縱向的深度：機制、因果、應用 | `references/thread-exam.md` |
| stolas-web 主檔 | 橫向的關係：定位、辨析、串聯 | `references/web-exam.md` |

兩者共用的評分、回饋、補測規則在 `references/grading.md`，第一次批改前讀取。

總原則：**驗收時，要求提取。** 題目要讓照抄教材或主檔答不出來；評分看意思對不對，不看措辭是否貼近原文。

## 步驟 1：找到要考的材料

依序判斷，找到就停：

1. 使用者在訊息中指定了檔名、附上檔案，或指定了主題名稱：用那一份。
2. 本對話中 stolas-thread 或 stolas-web 建立或更新過的檔案：用最近更新的那一份。本對話同時有兩份以上時，用選擇題框請使用者選。
3. 使用者連接的資料夾或工作目錄中，檔名以 `stolas-thread-`、`stolas-web-` 開頭 (舊版為 `stolas-`、`stolas-lite-`) 的 Markdown 檔：列出最近更新的 3 到 5 份，請使用者選。
4. 都找不到：請使用者附上教材或主檔。對話中有講解紀錄但檔案遺失時，說明可以先回 stolas-thread 或 stolas-web 依對話紀錄重建檔案，再來驗收。

**判斷來源**：讀 frontmatter 的 `type`。

- `stolas-thread`，或沒有 `type` 但 `tags` 含 `stolas` 的舊版教材：thread 模式。
- `stolas-web`，或舊版的 `stolas-lite`：web 模式。
- 兩者都不是：說明本技能只驗收 Stolas 系列的教材，請使用者確認檔案。

**讀取範圍**：thread 模式讀節點表、各節點小節、術語表、常見誤解、起點問題 (若有)、「驗收」章節，再找隱藏評分草稿 `.stolas-<slug>-rubric.md` (claude.ai 在 `/home/claude/`，其他環境在教材同層)。web 模式讀目錄樹、每個條目 (含收錄的比較表與比喻)、「驗收紀錄」章節。同一對話中有講解紀錄時，一併參考聊天中的完整講解與使用者的提問。

## 步驟 2：決定這一輪的範圍

**thread 模式**：

| 情況 | 這一輪 | 範圍 |
|---|---|---|
| 節點表仍有「待講解」節點 | 期中驗收 | 上次驗收後新講解 (或已寫教材) 的節點 |
| 沒有待講解節點 | 最終驗收 | 全部節點，加上先前未通過的補測 |
| 使用者說「跳至結尾驗收」，或指定要最終驗收 | 最終驗收 | 全部節點，含尚未講解的 |
| 期中範圍是空的 (上次驗收後沒有新講解的節點) | 說明目前沒有新內容可考，詢問要改做最終驗收還是先回去繼續教學 | |

**web 模式**：預設範圍是所有已建立條目的關鍵字 (待拆的詞不考)。使用者指定了某一支 (例如「K3 這一支」「只考 K1 到 K5」)，就只考那一支，以及與它有關聯線的詞。已建立條目少於 3 個時，說明材料還不夠出一輪題，請使用者先多拆幾個詞。

範圍決定後，用一兩句話告訴使用者這一輪考哪些節點或關鍵字、幾題，然後出題。

## 步驟 3：出題

依模式讀 `references/thread-exam.md` 或 `references/web-exam.md`，照其中的題型與出題規則出題。共同規則：

- **用文字作答，不使用選擇題框**。選擇題考的是辨認，驗收要考的是提取。
- 出完整批題目後、送出前，做一次 `references/grading.md` 的「跨題檢查」。
- 每題的核心要素寫進隱藏評分草稿 (thread 模式寫進 `.stolas-<slug>-rubric.md`；web 模式寫進 `.stolas-web-<slug>-rubric.md`，位置規則相同)。草稿中已有 stolas-thread 判定深淺時寫的考題，優先沿用或改寫，不從零開始。
- thread 的最終驗收題目先寫進教材「驗收」章節並標「待完成」，使用者當下離開也能之後接續作答。
- 題目送出後本輪結束，等使用者作答。

## 步驟 4：批改

依 `references/grading.md` 逐題評分與回饋。**批改那一則只回覆評分與回饋，然後停下等待使用者**，不要在同一則接著補測、講下一個節點或結案。使用者需要時間消化回饋，也可能想針對回饋追問。

批改那一則的最後，用一行說明接下來可以做什麼：

- 有未掌握的題：`輸入「補測」針對未掌握的部分再考一題，或直接追問回饋內容`
- thread 期中驗收全部通過：`可以回到 stolas-thread 繼續教學`
- thread 最終驗收各題都達到掌握或部分掌握：`可以回到 stolas-thread 說「結案」，結案後由 stolas-print 產出 PDF 學習筆記，驗收紀錄會收進附錄`
- web 模式：`驗收紀錄已寫入主檔，可以繼續拆新詞`

## 步驟 5：寫回原檔

批改後立即寫回，再呈現檔案 (寫在使用者本機資料夾時，告知已更新即可)。用局部編輯，只動下列區塊。

**thread 教材**：

1. **節點表**：答對的節點狀態改為「已掌握」；部分掌握的備註加「建議複習」；補測兩次仍未掌握的備註加「需再複習」。「跳至結尾驗收」中未講解卻答對的節點，直接標「已掌握」。
2. **「驗收」章節**：每輪一個小節，標題寫「期中驗收 第 N 輪」或「最終驗收」，內容為範圍、題目、作答摘要、評級、回饋重點、補測結果，以及跨題模式 (有的話)。
3. **補講內容**：未掌握而補講的內容，整併進該節點的小節 (重寫成通順的講義段落)；「跳至結尾驗收」中答不出來的未講解節點，補上對應小節，狀態改為「已講解」。新出現的術語寫進術語表。
4. 版本號 +1，版本紀錄寫一列 (例如「期中驗收第 1 輪，N1 到 N3」)。
5. 不寫一頁重點、不改學習狀態、不產 PDF，這些由 stolas-thread 的結案階段與 stolas-print 處理。

**web 主檔**：

1. 在「資料來源」之前建立或更新「## 驗收紀錄」章節，每輪一個小節：日期、範圍、每題一列「題目摘要、涉及的關鍵字、評級、回饋重點」，最後一行「建議複習：K<m>、K<n>」(沒有時省略)。
2. 回饋中修正了某個條目的一句話白話版或位置關係時，同步更新該條目、目錄樹與心智圖。
3. 不在條目或目錄樹上加掌握標記，主檔維持速查表的克制。
4. 更新 frontmatter 的 `updated`。

## 補測與結束

- 使用者說「補測」：依 `references/grading.md` 的「補強與補測」，針對未掌握的節點或關係出一題新情境的題目，批改規則相同。
- 使用者說「結束驗收」或改去做別的事：未作答的題目在紀錄中標「未作答」，結束這一輪。
- thread 最終驗收結束後，回到 stolas-thread 的流程由使用者決定；本技能不自動結案。

## 語言與格式

- 使用繁體中文，專有名詞附原文，用詞與教材或主檔的主名稱一致。
- 中文使用全形逗號與句號，括號一律半形，括號與前後中文各留一個空格。英文句子全用半形標點。
- 補充說明用括號。
- 不使用 emoji。
- 直接陳述正確的內容 (避開「不是……而是……」句式)。
- 段落以陳述句收尾 (避開反問句)。

## 模型補丁

**Opus 系列**

- 批改後一律停下，只回覆批改意見，不要熱心地接著補測、講下一個節點或直接結案。
- 跨題檢查逐題執行，不以「題目看起來不同」略過。

**Sonnet 系列**

- 評分時先列出每題的核心要素再比對作答，避免因措辭和教材不同而降級。

## 備援規則

- **評分草稿不見了**：依教材或主檔中的題目與講解內容重新擬定核心要素。
- **原檔在出題後被改動** (例如使用者在檔案上加了註解)：寫回前重新讀取，只更新本技能負責的區塊。
- **工具呼叫失敗**：改用下一個替代方案；完全無法寫檔時，把要寫回的區塊以 Markdown 貼在聊天中，請使用者自行貼上。

## 參考檔案

- `references/thread-exam.md`：thread 教材的題型 (術語單元、經典文本單元)、出題規則、回扣起點問題。thread 模式出題前讀取。
- `references/web-exam.md`：web 主檔的關係題型與出題規則。web 模式出題前讀取。
- `references/grading.md`：跨題檢查、評分草稿、評分、回饋、補強與補測。第一次出題後、批改前讀取。
